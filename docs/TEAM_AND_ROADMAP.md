## 模块交付与验收

| Owner | 主目录 | 最小交付物 | 验收人 | 完成定义 |
| --- | --- | --- | --- | --- |
| A | `experiments/`、`results/` | 归因/指标实现、配置 schema、`run_unit.py`、断点续跑、逐图和聚合 CSV | C、D | 一条命令完成一个实验单元；配置、日志和结果可对应，失败单元可续跑 |
| B | `data/`、`preprocessing/` | 固定数据清单、加载器、`metadata.csv`、复核记录 | A、D | 其他成员按 README 在 10 分钟内加载同一评估集，样本和标签可追溯 |
| C | `models/`、环境与主线入口 | 统一模型接口、准确率表、冒烟测试、环境配置和仓库集成 | A | 任一模型可被实验入口直接调用；干净环境可按 README 跑通主线 |
| D | `analysis/` | 长表、统计检验脚本、图表、RQ1–RQ3 结论和选择指南 | B、C | 每张图和每条结论均可由脚本从结果文件复现 |
| E | `docs/`、`README.md` | 阶段材料、报告、PPT、固定 Demo 流程和会议纪要 | 全员 | 新成员可按 README 复现；汇报材料中的数字与主线结果一致 |

## 阶段路线图

### M2：先打通最小闭环（09-18 前）

- A：接入 Grad-CAM、IG 两种方法，并交付单单元实验配置、指标和结果 CSV。
- B：冻结 debug 集和正式评估集，交付 metadata 与数据核验说明。
- C：交付 3 个模型统一接口和环境基线，与 A 联调“数据 → 模型 → 归因 → 指标 → CSV”闭环。
- D：交付结果聚合脚本和首张对比图模板。
- E：交付 README 运行入口、固定 Demo 顺序和 M2 展示材料。

### M3：形成可比较结果（09-25～10-02）

- A：至少 4 种方法在 debug 集跑通，并启动正式矩阵；C 负责模型、环境和接口异常支援。
- B：抽检样本、标签、预测和指标值，形成异常清单。
- D：形成 Pareto、交互效应和相关性初版。
- E：完成中期 PPT、讲稿和固定演示数据。

### M4：完成全矩阵与统计结论（10-16 前）

- A 对 36 个主体单元的完成率、运行日志和方法异常负责；C 对模型、环境与主线集成负责；B 对数据和指标输入质量负责。
- D 完成 ANOVA/非参数替代、效应量、相关性和方法选择指南初版。
- E 将可复现结果同步进报告，不接受只有截图、没有脚本或结果表的结论。

### M5：仓库和答辩收口（11-06 前）

- C 从干净环境按 README 复现主线；A 冻结实验结果并整理配置/日志；B/D 交叉复核数据和结论。
- E 统一报告、PPT、图表与 Demo 口径，并组织至少两轮答辩演练。
- 冻结后只接受文档修正或阻断演示的缺陷修复。

## 协作规则

- `main` 始终可复现；分支使用 `feat/`、`research/`、`fix/`、`docs/` 前缀。
- 每个 PR 至少一名非作者审阅；跨模块改动必须由验收搭档参与。
- PR 写明运行命令、验证结果、数据/配置版本和已知限制；生成数据和模型权重不进 Git。
- 每周例会由 E 主持、C 维护看板；每人只汇报“已完成、阻塞、下一步”三项。
- 实验模块延期超过 2 天时，A 当天拆出最小可运行矩阵；C 协调接口和环境支援，E 调整展示范围。

更完整的技术方案、实验矩阵、风险和结果 schema 见 [`../XAI01-04_小组工作指导.md`](../XAI01-04_小组工作指导.md)。
