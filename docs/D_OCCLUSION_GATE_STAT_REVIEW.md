# 成员 D：PR #13 Occlusion 门禁与统计口径复核

复核日期：2026-09-26。复核对象：PR #13，头提交
`6d5645fecfcfdc0af1665435186a81f775faf8e2`。

## 结论

成员 D 对 PR #13 给出**有条件通过**：六组合单图与 40 张 debug 门禁足以证明当前
Occlusion 配置可执行、输出结构可供后续统计使用；PR 可以作为工程门禁和正式配置候选继续
审查。但当前证据不能证明参数最优，也不能把 40 张结果写成正式方法排名。启动 460 张正式
eval 前仍需组内明确冻结参数、输出目录和硬件计时口径。

## 已确认的统计契约

- 六组合均固定 `32×32` 遮挡窗、`16×16` 步长、
  `perturbations_per_eval=16`，避免模型或数据集间参数漂移。
- 主忠实性字段是 `faithfulness_morf_auc_raw`，21 个删除比例点，方向为 **min**；
  legacy ratio AUC 不进入 ANOVA、Pareto 或正式排名。
- ImageNet 使用 softmax、VOC 使用 sigmoid。两者的 raw AUC 概率语义不同，必须把
  `dataset` 保留为分层/因子，不能直接以跨数据集平均值宣称方法优劣。
- 40 张门禁和 460 张 eval 使用不同 split、配置哈希、结果目录及状态目录；六个正式单元
  也各有独立目录，可以避免续跑和清理互相覆盖。
- 门禁报告称每单元 40 张、0 失败、0 常量图，float32 map 有限且位于 `[0,1]`；
  这些数值目前是 PR 文档中的报告结果，不是 D 独立重跑结果。

## 正式运行前必须处理

### 1. 统一效率硬件口径

PR #13 的门禁环境是 RTX 5080 Laptop GPU；A 的 IG/Grad-CAM 正式结果来自 RTX 2080 Ti，
D 当前可用机器是 RTX 4060 Laptop GPU。不同 GPU 的 `efficiency_time_ms` 不能直接用于
跨方法显著性检验或三指标 Pareto，否则硬件差异会和方法效应混杂。

正式效率比较应选择以下一种口径并写入报告：

1. 所有方法在同一台机器、同一软件环境上重跑计时；或
2. 按硬件分层报告，不做跨硬件耗时排名；或
3. 另设统一小型计时基准，仅将该基准时间用于跨方法 Pareto。

在口径冻结前，Occlusion 的门禁耗时只用于预算，不进入最终方法排名。

### 2. 提交机器可读的门禁摘要

PR 当前提交了 Markdown 表格，但逐单元 `gate_report.json` 位于被忽略的结果目录。建议在
不提交图片、checkpoint 或逐图 NPY 的前提下，增加一个可版本化的 JSON/CSV 摘要，至少包含：

- PR 头提交、数据版本、配置哈希和权重 SHA-256；
- 模型、数据集、样本数、失败数、常量图数；
- raw AUC 与归因耗时的 `mean/min/max`；
- GPU、PyTorch、CUDA 和 Captum 版本。

没有该摘要时，D 只能复核文档口径，不能从仓库内证据独立重算表格。

### 3. 明确六目录合并流程

六个正式单元分别写入 `results/occlusion_eval/<model>_<dataset>/`，而现有
`analysis.aggregate` 每次只接收一个 `per_image.csv`。正式运行前需要冻结一个确定性的合并
清单或合并脚本，只合并 460 张 eval 文件，并在合并后执行 schema、重复键、每单元 `n=460`
和 `config_hash` 校验。不得混入 single/debug40、旧 ratio pilot 或其他硬件上的计时行。

### 4. 限定参数结论

当前 40 张门禁只检验了一个窗/步长候选，因此可以支持“该候选可运行”，不能支持“该参数
最优”。若组内直接冻结，应在报告中表述为预先固定的工程选择；若要宣称质量优势，需要在
同一冻结子集上增加候选参数敏感性比较。

## 与 PR #10 的边界

本复核不替代稳定性协议的 C/D 最终确认。PR #13 只提供 Occlusion 原始 float32 map 和候选
正式配置；稳定性 trace/state 隔离、原图与配置/权重身份绑定、以及基础 runner 可能改写稳定性
`config_hash` 的问题仍应在 PR #10 集成前解决。
