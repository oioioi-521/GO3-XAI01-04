制定日期：2026-09-11。状态：方案已制定，P0–P4 主试跑与 P5 选做前沿探针均已完成。P0–P4 的逐项计时字段合计约 15.9 分钟（不含模型加载、预热与调度间隙），原执行记录按含这些开销的 GPU 墙钟估计约 20 分钟，低于 120 分钟上限；P5 另有约 12.8 分钟逐项计时。总览见 `RESULT_INDEX.md`，成本外推见 `extrapolation.md`。本轮获准累计 GPU 试跑时间约 2 小时以内；这是上限，不要求耗尽。

## 1. 依据与边界

|---|---|---|
| 方法 | Grad-CAM、IG、SHAP、RISE、LIME、Ablation；建议 ≥4 | 6 种先少量测成本，SHAP 明确为 KernelSHAP |
| 模型 | VGG-16、ResNet-50、DenseNet-121；建议 ≥2 | 3 种预训练模型少量计时，之后选择 2 种作为主体 |

本轮目的：测清归因、评价、数据准备各自的开销，建立可外推的成本表，而不是训练模型或宣布某方法最优。所有采样数、224×224 输入、批量、噪声幅度、时间上限都是本方案的操作性选择，并非 PDF 的规定。

## 3. 分阶段试跑

| 阶段 | 内容 | GPU 时间分配上限 | 完成标准 |
|---|---|---:|---|
| P0 环境与首通 | 版本/权重/数据来源；ResNet-50 + Grad-CAM / KernelSHAP 首通 | 15 分钟 | 真 CUDA 执行、结果有限、分段计时能落盘 |
| P1 成本校准 | 6 方法 × 3 模型；同一输入尺寸；至少一次预热与 3 次计时 | 15 分钟 | 18 个方法模型组合有时间/显存或明确失败状态 |
| P2 小型完整评价 | 2 数据集 × 3 模型 × 6 方法 × 每数据集 4 张起步，争取 8–16 张 | 55 分钟 | 同一图配对、归因 + 忠实性 + K=2 稳定性；逐条保存 |
| P3 成本曲线 | 少数固定图上 IG 步数、随机方法采样数、内部 batch 扫描 | 20 分钟 | 至少低/中档成本；能判断批量与采样是否主导开销 |
| P4 复核余量 | 重跑异常、另一随机种子或更高档参数验证 | 15 分钟 | 说明波动与外推误差；预算不足则不做 |

总上限 120 分钟，包括预热、校准、失败和重跑期间的 GPU 占用墙钟，不只累加 CUDA kernel 时间。下载、安装、CPU 分析另外计时；总任务经过时间可能更长。阶段可提前结束；慢方法以小样本覆盖优先，不能为了用满预算扩大任务。runner 必须设全局 deadline 和单项 timeout，超时记为删失/失败，不能记录为一个正常完成的耗时。

初始参考配置：外层每次 1 张，FP32、eval 模式，224×224，关闭训练；内部 batch 从 8 或 16 开始，按 8/16/32 小扫。不先用 AMP/编译改变归因数值与冷启动成本。若需改变精度，另开配置并先核对归因差异。

| 方法 | 首轮设置 | 少量成本曲线 | 主要成本项（只表示工作量，不是硬件时间预测） |
|---|---|---|---|
| Grad-CAM | 最后一个适合的卷积层，记录层名 | batch 校准 | 一次前向与反向及热图处理 |
| IG | 黑色图像基线，32 路径点 | 16 / 32 / 64 点 | 路径点上的前向与输入梯度 |
| KernelSHAP | 7×7 共 49 个特征组，512 样本 | 128 / 512 / 2048 样本 | 扰动推理 + CPU 加权回归 |
| RISE | 512 masks，记录低分辨率网格与保留概率 | 128 / 512 / 2048 masks | mask 构造/上采样 + 扰动推理 |
| LIME | 与 KernelSHAP 相同的 49 特征组，512 样本 | 128 / 512 / 2048 样本 | 扰动推理 + CPU 局部回归 |
| Ablation | 逐一移除 7×7 非重叠区域 | 可选 8×8 对照 | 原图 + 每个区域的扰动推理 |

这里 LIME / KernelSHAP 的规则网格是便于对齐成本的特征分组，不冒充自适应超像素。若改成超像素，必须单独记录分割耗时、实际特征数并重新计时。Ablation 指输入区域消除，不是 Ablation-CAM。不能用不同 SHAP 变体的时间互相替代。中高采样档若未运行，则保留为待测。

## 4. 数据与模型语义

准备少量真实数据，并记录源 URL、版本/split、采样规则、图像 ID、SHA256、图像尺寸和可得的标签/病人 ID。固定种子选样，所有方法与模型使用相同图像；先试 4 张再扩充到 8 或 16，原有图保持包含关系。计时校准可以用明确标为 synthetic 的输入，但不能据此填入真实数据集质量结果。

ImageNet 预训练分类头直接作用于 CHNCXR 时输出不是疾病预测；VOC 多标签也不自动等同于 ImageNet 类别。本轮可测其真实输入上的运行成本，并以 `quality_scope=ood_pipeline_diagnostic` 保存解释管线诊断，不能解释成医学忠实性或已完成跨任务有效性验证。

正式实验开始前需要匹配数据任务的模型/类别映射：ImageNet 使用对应类别；VOC 使用明确的类别映射和目标选择协议或适配后的分类器；CHNCXR 使用可靠的任务检查点与患者级数据划分。若需要微调，单独计入训练成本，当前试跑不包含。最终两数据集优先按任务匹配情况选择，不能只因为方便下载而确定。

每个模型按原图预先确定解释 target，后续所有方法、扰动、Insertion/Deletion 均固定此 target。若两个模型的 target 不同，记录这一事实；正式研究“方法 × 模型”质量交互时应固定可比较的语义目标，或把目标选择差异列为实验条件。不得把扰动后的 top-1 重新当 target。

## 5. 指标协议与成本复用

1. **效率**：分别测数据加载/预处理、模型加载/预热、原始归因、Insertion、Deletion、稳定性、文件写入及整个任务的墙钟。用 `torch.cuda.synchronize()` 包围 `perf_counter`；CUDA event 可辅助，不能替代包含 CPU 回归与同步等待的总耗时。报告均值、中位数、最小/最大以及样本数；有足够计时样本后再提供 p90/p95。总预算外推用均值，不能直接把中位数之和当预期总成本。
2. **忠实性**：从缓存归因图生成固定目标概率曲线；20 个删除/插入步长、21 个节点，按被替换比例做梯形积分。Insertion AUC 越高、Deletion AUC 越低是该具体协议下的方向。记录替换基线和排序规则。端点/预测在协议相同时复用；不能把两条曲线当作需要两次重算归因。
3. **稳定性**：主试跑 K=2 个小扰动输入各重新求归因，再计算与原图归因的 cosine。建议原始 [0,1] 图像空间加 sigma=0.01 高斯噪声并裁剪；实际参数必须存储。全方法共享扰动图。对于随机方法，同一原图/扰动图配对复用随机 masks 或 RNG，用于测输入变化；另外改变归因 seed 才用于测 Monte Carlo 噪声。两类不混为一个稳定性数字。K=2 仅估时，不能声称测得真实最大敏感性。
4. **归因规范**：保存原始带符号热图，记录通道聚合、正贡献/绝对值规则、上采样与归一化；供评价的共同规则必须一致并命名。零图/非有限值单列无效，不将其 cosine 强填为 1。原始图与归一化图分开，以便后续改变指标无需重算归因。

统计分析阶段可从同一批逐图指标构造 Pareto 图、相关性与交互效应分析，无需重新归因。效率至少保留“归因耗时”和“整个评价耗时”两种定义，分别回答部署解释成本与课题实验预算问题。

## 6. 外推与组合爆炸

设方法 a、模型 m、数据集 d、配置 h 的原图归因均值为 A，Insertion 为 I，Deletion 为 D，一次扰动重新归因及比较为 S，加载/写入等每图开销为 O。每个数据集 N 张、每个随机配置 R 次重复、K 次稳定性扰动：

`T = T_setup + Σ[a,m,d,h] N[d] × R[a,h] × (A + I + D + K×S + O)`

这里 setup 包括每次实际发生的模型加载与预热；下载/安装单列为一次性成本。若 S 尚未测量，可以临时用 A 作为假设，但必须标注，不能当实测。把单方法 t 秒/图換算为 100、500、1000 张的时间，1 小时 = 3600 秒；矩阵时间按所有条件求和。小样本不宜伪造置信区间：先给样本范围、基于均值的点估计及 30% 工程余量，后者不是统计置信区间。

全候选有 `6×3×3=54` 个方法模型数据条件。忠实性/稳定性/效率是评价输出，不能简单称为 162 次互不复用的归因实验。若每条件 N 张、R 个随机种子、K 次稳定性扰动，则归因调用约为 `54×N×R×(1+K)`；另外再加忠实性前向与数据/CPU开销。不同方法自身每次归因的采样数也完全不同。

建议主体先保留 **Grad-CAM、IG、KernelSHAP、RISE × 两种模型 × 两个任务匹配的数据集 = 16 个条件**，每数据集先 100 张配对样本，K=2，随机方法先一个 seed。LIME/Ablation 与第三个模型在小型矩阵做补充。模型选择由实测内存/时间及架构覆盖共同决定，不预先凭参数量猜速度。

仅条件数从 54 到 16 减少约 70.4%，实际 GPU 节省取决于保留哪些方法，不能直接照搬这一百分比。相对于每条件 500 张，先用 100 张则样本项减少 80%；稳定性 K=10 改为 K=2 时归因调用项从 11 降至 3，但忠实性/IO 成本并不等比例下降。必须代入本次分段计时算总收益。

控制组合的顺序：

- 首先固定分辨率、基线、评价步数与默认采样数，避免所有超参数再做笛卡尔积。
- 保留主体 `方法 × 模型 × 数据集` 完整交叉，方便回答交互问题；不随机删掉关键条件。
- 超参数成本曲线只在固定的校准图上测；高成本设置没有明显稳定性收益时不扩展。
- 用类别/置信度分层的相同图像子集递增到 100、200、500，保留另一个确认子集；患者数据按患者分层与划分。
- 先报告配对差异及不确定性，再决定是否追加样本/种子；探索阶段挑出的赢家必须在保留样本上确认，不能用同一小样本选择并宣称显著。
- 随机方法在小子集测 seed 方差，再决定哪些需要 3 seeds；确定性方法不为凑 seed 数重复质量计算。
- 归因、原图预测、相同基线端点、曲线、扰动图均缓存；seed/target/权重/配置变化时严格更换缓存键。
- PDF 的 Latin Hypercube 更适合连续超参数探索；类别型的核心交叉矩阵优先平衡分层，不把 LHS 当作保证所有方法模型交互可估计的替代品。

正式统计中，图像是配对/重复测量单元，嵌套于数据集；同一图的多个方法、扰动和 seed 不是独立样本。使用能表达这一结构的重复测量/混合效应分析，报告效应量、区间与多重比较处理。小试跑不做确定的 ANOVA/Pareto 优胜结论。

## 7. 原始记录与复现交付

每个任务至少保存如下字段，未测量用 null 和缺失原因，不填 0：

- 标识：run_id、config_hash、UTC时间、主机、代码版本/hash、源 PDF hash。
- 软件硬件：Python/PyTorch/torchvision/解释库版本、CUDA runtime、cuDNN、GPU/驱动、CPU/RAM、启动前空闲显存。
- 数据模型：dataset/version/split、sample_id/image hash、真实/合成标识、抽样seed、目标类、原始分数/标签/正确性可用性、模型名/权重来源与hash、预处理、输入尺寸。
- 方法：确切算法/变体、层名、baseline、feature mask、采样数/路径点、外层与内部batch、dtype、解释seed、扰动seed、K、metric steps、质量范围标记。
- 时间：setup/load/preprocess/warmup/attribution/insertion/deletion/stability/io/end_to_end，各单位秒；测时是否同步；GPU event毫秒另列；全局实际经过时间。
- 工作量：模型前向调用批次数、前向实际图像/扰动样本数、反向调用数；明确是否包含评价。
- 资源：CUDA max allocated/max reserved，CPU RSS峰值或采样峰值，GPU全局显存采样、利用率、功率、温度及采样间隔；若记录能耗，注明采样积分和是否扣除桌面空闲基线。
- 结果：Insertion/Deletion节点和AUC、逐扰动cosine、无效归因比例、原始/处理后归因缓存路径。
- 状态：ok/oom/timeout/error/skipped、失败阶段和原因、完成任务数、retry与降batch历史。

建议交付：本方案 `PLAN.md`；数据来源与manifest；独立运行脚本与参数；环境快照；追加写入的 JSONL 原始记录；配置与归因缓存；结果汇总 Markdown/JSON；100/500/1000 图各条件与主体矩阵的外推表。格式以 runner 最终实际输出为准，并在结果索引中链接。
