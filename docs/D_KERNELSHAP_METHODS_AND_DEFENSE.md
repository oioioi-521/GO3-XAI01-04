# D：KernelSHAP 方法说明、正式结果与答辩要点

2026-10-27；可供 A 合入报告 §2.3/§3/§8，E 整理讲稿。以下项目数值只来自冻结 DCU 批次，
不混入旧 RTX/Windows 门禁或正式运行；统计来源为 [D 正式报告](DCU_STATISTICAL_ANALYSIS_20261015.md)。

## 可直接合入报告的方法段落

KernelSHAP 用特征联盟采样和带 Shapley 核的局部加性模型估计各特征相对基线的贡献。
本项目调用 Captum `KernelShap`，以冻结 metadata 的真值类别索引为 target，解释模型的该类 logit。
输入为 224×224，RGB 通道共享 7×7 规则网格的 49 个特征组，未选中的组替换为归一化黑图基线
`−mean/std`。六个正式配置均为 `n_samples=2048`、`perturbations_per_eval=16`、`seed=42`。
这近似的是当前特征分组和基线定义下的贡献，未枚举全部联盟，也没有据此证明采样收敛。

适配器将带符号的通道贡献取均值，再 min-max 归一化为二维 `[0,1]` 图，保存 float32 NPY；
PNG 是量化预览。排序保持符号方向，不用绝对值把负贡献排成强正证据。归一化后的图用于排序、
删除评价和 Spearman 稳定性，不能直接声称仍具有原始 Shapley 贡献之和等于 logit 差的数值性质。

删除忠实性另在真值类别概率上计算 raw MoRF AUC：ImageNet 使用 softmax，VOC 使用 sigmoid，
删除比例 0 至 1、步长 0.05，共 21 点，AUC 越低越好。解释 target 同为真值索引，
但归因 logit 与评价概率是不同响应量。稳定性每图加入五次 RGB 高斯噪声，sigma=0.005，
配对 seed 由数据集/图像/repeat 派生；固定方法 seed 不等于测量联盟重采样不确定性。

实现：[kernelshap.py](../experiments/attribution/kernelshap.py)、
[runner](../experiments/run_unit.py)、[metrics](../experiments/metrics.py)。
正式参数以原交接包 `configs/five/kernelshap-*/configs/*_unit.yaml` 为准；类构造器的默认参数不是正式预算。
这次核对六份冻结配置均为上述 2048/16/7/42。

KernelSHAP 位于六组质量双目标前沿中的五组，例外为 ImageNet/ResNet50。
ImageNet/DenseNet121 的 AUC 均值点估计最低，但相对 IG 的均值差区间跨零，
配对秩方向偏 IG；应保留 [三口径核对](D_M5_STATISTICAL_CONFIRMATION_20261027.md)，不能写成 KernelSHAP 均值显著最优。
质量前沿和统计显著性是不同概念；不同数据集的 AUC 也不能跨表混排。

## 限制与 60 秒讲述

限制包括规则网格的粗粒度、黑图替换引入的分布变化、单个 2048 采样预算与单个方法 seed、
归一化后贡献幅度含义改变，以及课程固定子集/权重的外推限制。高输入噪声稳定性不自动代表
解释更忠实，也不证明定位正确或因果有效；本批次共享 DCU 时间不外推为硬件速度保证。

> 我负责 KernelSHAP 的实现与实验，以及组内统计汇总。正式 KernelSHAP 使用 7×7 网格，
> 将像素合为 49 个区域，按 2048 个联盟采样估计各区域相对黑基线的贡献。
> 我们保存原始精度的归一化图，统一做删除忠实性和五次输入噪声稳定性评价。
> KernelSHAP 在五组质量前沿上，但不存在全指标通用冠军；DenseNet/ImageNet 的均值优势也未被区间证实。
> 我们将均值、配对秩、前沿和计时边界分开解释，不把热图清晰或稳定当成因果正确的证明。

## 常见答辩问题

| 问题 | 可用回答 |
|---|---|
| 为什么不按每个像素计算精确 Shapley？ | 联盟数随特征数指数增长；本项目限定 49 个区域和 2048 采样以控制计算，结论条件于该粒度/预算。 |
| SHAP 是不是对所有背景图平均？ | 当前 Captum 调用使用固定黑基线替换缺失区域，没有采样背景数据分布；解释受基线选择影响。 |
| 为什么解释 logit 却评价概率？ | 真值类别索引一致，但两者响应不同；这是冻结实现，不隐瞒这种比较边界，也不能据此宣布满足所有方法可比性假设。 |
| 热图是否保留正负贡献原值？ | 带符号通道均值参与排序，再 min-max；最终 NPY 不保存原始未归一化贡献幅度，不能据它验证贡献可加和。 |
| 2048 是否足够收敛？ | 运行完整性和可续跑得到检查，但本次不是预算收敛实验，不能证明已收敛。 |
| 为什么均值更好却秩检验偏向另一个方法？ | 均值与按差值秩加权的统计量不同；在该例中需同时保留均值区间跨零和秩方向偏 IG 的事实。 |
| 你个人做了什么、DCU 又是谁跑的？ | 区分方法/代码与统计责任、历史本机运行、共享 DCU 执行及验收；不把别人执行的统一批次全部说成本人计算。 |
